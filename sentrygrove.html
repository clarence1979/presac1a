Lights

about 20 minutes
Goal

Make the green and red LEDs take turns blinking, and understand the 5-byte message that makes it happen.

How the Pi talks to the board

Your Python program does not switch the LED on by itself. It sends a short message over two wires (called I2C) to a small chip on the GrovePi+, and that chip does the work. Every message is exactly five bytes (a byte is a number from 0 to 255). Press a button to watch a message travel.

Command numberMeansPortValue
5Set up a portD2, D3, ...1 = output (we will drive it), 0 = input
2Switch a port on or offD2, D3, ...1 = on, 0 = off
7Measure distance (Mission 2)D5ignored
3Read a light level (Mission 2)A0ignored
4Play a tone (Mission 3)D6128 = tone on, 0 = off
40Read temperature and humidity (Mission 4)D80 = blue DHT11 sensor

The program

Read the comments (the green text). Each function wraps one message so the main program at the bottom reads like English: turn_on(green_led_port).

mission1_lights.py
# Mission 1 - LIGHTS
# GrovePi+ on a Raspberry Pi 5 (Kali Linux)
#
# Plug in:    Green LED -> D2        Red LED -> D3
# Run with:   sudo python3 mission1_lights.py       (Ctrl+C to stop)
#
# What you learn: how the Pi talks to the GrovePi+ board.
# Every message to the board is 5 bytes:   1, command, port, value, 0

import os
import fcntl
import struct
import time
import signal

# ---------- Settings you can change ----------
green_led_port = 2
red_led_port = 3
blink_speed = 0.5         # seconds each LED stays on


# ---------- Connecting to the GrovePi+ ----------
# The GrovePi+ listens on the I2C wires at address 4.
def open_device(address):
    device = os.open("/dev/i2c-1", os.O_RDWR)
    fcntl.ioctl(device, 0x0703, address)     # 0x0703 means "talk to this address"
    return device


# ---------- GrovePi+ helpers ----------
# Every GrovePi+ message is 5 bytes: 1, the command number, the port, a value, 0
def grovepi_send(command, port, value):
    message = struct.pack("BBBBB", 1, command, port, value, 0)
    os.write(grovepi, message)
    time.sleep(0.02)                 # give the board a moment to read it


def make_output(port):
    grovepi_send(5, port, 1)         # command 5 = set a port to be an output


def turn_on(port):
    grovepi_send(2, port, 1)         # command 2 = digital write, 1 = on


def turn_off(port):
    grovepi_send(2, port, 0)         # 0 = off


# ---------- Set up ----------
signal.signal(signal.SIGINT, signal.SIG_DFL)     # make Ctrl+C stop the program quietly

grovepi = open_device(0x04)
make_output(green_led_port)
make_output(red_led_port)

print("Blinking! Press Ctrl+C to stop.")

# ---------- Main program ----------
while True:
    turn_on(green_led_port)          # green on, red off...
    turn_off(red_led_port)
    time.sleep(blink_speed)
    turn_off(green_led_port)         # ...then swap
    turn_on(red_led_port)
    time.sleep(blink_speed)

Eyes

about 25 minutes
Goal

Read the ultrasonic ranger and the light sensor, print the numbers, and turn the red LED on when something comes closer than 50 cm.

How the ranger measures distance

The ranger shouts a click too high for you to hear, then listens for the echo. Sound travels at about 343 metres per second, so the longer the echo takes, the further away the object is. The GrovePi+ does the maths and hands back the distance in centimetres. Drag the slider to move the object.

Reading the answer

Sending a message is Mission 1. The new part is reading the reply. The board answers with three bytes. A byte only goes up to 255, so a distance like 300 cm would not fit in one byte. The board splits the number into a "high" byte and a "low" byte, and your program joins them back together:

Try the slider above 255 cm and watch the high byte change from 0 to 1.

The program

Everything with a green bar is new. grovepi_answer() reads the three bytes; read_distance() and read_light() each send a question and then wait for the answer.

mission2_eyes.py
# Mission 2 - EYES
# GrovePi+ on a Raspberry Pi 5 (Kali Linux)
#
# Plug in:    Green LED -> D2       Red LED -> D3
#             Ultrasonic ranger -> D5        Light sensor -> A0
# Run with:   sudo python3 mission2_eyes.py        (Ctrl+C to stop)
#
# What you learn: asking the board a question and reading its answer.
# The ranger measures distance in cm. The light sensor gives 0 (dark) to 1023 (bright).
# If something comes closer than the tripwire distance, the red LED comes on.

import os
import fcntl
import struct
import time
import signal

# ---------- Settings you can change ----------
green_led_port = 2
red_led_port = 3
ranger_port = 5
light_port = 0            # A0
tripwire = 50             # cm - closer than this = red LED


# ---------- Connecting to the GrovePi+ ----------
def open_device(address):
    device = os.open("/dev/i2c-1", os.O_RDWR)
    fcntl.ioctl(device, 0x0703, address)     # 0x0703 means "talk to this address"
    return device


# ---------- GrovePi+ helpers ----------
# Every GrovePi+ message is 5 bytes: 1, the command number, the port, a value, 0
def grovepi_send(command, port, value):
    message = struct.pack("BBBBB", 1, command, port, value, 0)
    os.write(grovepi, message)
    time.sleep(0.02)


# The GrovePi+ answers with 3 bytes: a label, then a number split into two bytes
def grovepi_answer():
    reply = os.read(grovepi, 3)
    label, high, low = struct.unpack("BBB", reply)
    return high * 256 + low          # join the two bytes back into one number


def make_output(port):
    grovepi_send(5, port, 1)         # command 5 = set a port to be an output


def turn_on(port):
    grovepi_send(2, port, 1)         # command 2 = digital write, 1 = on


def turn_off(port):
    grovepi_send(2, port, 0)         # 0 = off


def read_distance():
    grovepi_send(7, ranger_port, 0)  # command 7 = ultrasonic read
    time.sleep(0.1)                  # wait for the echo to come back
    return grovepi_answer()


def read_light():
    grovepi_send(3, light_port, 0)   # command 3 = analog read (0 = dark, 1023 = bright)
    time.sleep(0.05)
    return grovepi_answer()


# ---------- Set up ----------
signal.signal(signal.SIGINT, signal.SIG_DFL)     # make Ctrl+C stop the program quietly

grovepi = open_device(0x04)
make_output(green_led_port)
make_output(red_led_port)

print("Watching... Press Ctrl+C to stop.")

# ---------- Main program ----------
while True:
    distance = read_distance()
    light = read_light()
    print("Distance:", distance, "cm    Light:", light)

    if distance > 0 and distance < tripwire:     # 0 means nothing in range
        turn_on(red_led_port)                    # something is close!
        turn_off(green_led_port)
    else:
        turn_off(red_led_port)
        turn_on(green_led_port)

    time.sleep(0.3)

Voice

about 25 minutes
Goal

Count down on the LCD with a beep each second, play a "nee-naw" siren, then show a green "All clear".

Two noises, one siren

The speaker on the GrovePi+ can only play one pitch, and the buzzer only has one pitch too. On their own each is just a flat tone. But if they take turns every 0.3 seconds, you get a siren. That is what the siren() function does, using a for loop to repeat the pair.

(3 seconds, quiet)

Talking to the screen

The LCD is two devices in one: address 0x3E is the text, and 0x62 is the coloured backlight. Each line holds exactly 16 characters, so messages must be short. lcd_show(line1, line2) writes both lines, and lcd_colour(red, green, blue) mixes a colour from three numbers between 0 and 255. Press Run demo to see what the program below does on the screen.

The program

New this mission: the speaker helpers, siren(), and all the LCD helpers. Look at lcd_write_line(): the LCD wants letters as numbers, and ord("A") gives you the number for A (it's 65).

mission3_voice.py
# Mission 3 - VOICE
# GrovePi+ on a Raspberry Pi 5 (Kali Linux)
#
# Plug in:    Speaker -> D6       Buzzer -> D7       LCD RGB Backlight -> any I2C port
# Run with:   sudo python3 mission3_voice.py
#
# What you learn: making sounds and writing on the screen.
# The program counts down on the screen with a beep each second,
# then plays a "nee-naw" siren, then shows a green "All clear".

import os
import fcntl
import struct
import time
import signal

# ---------- Settings you can change ----------
speaker_port = 6          # must be D3, D5 or D6 - only these ports can play a tone
buzzer_port = 7
countdown_from = 5        # seconds
sound_on = True           # set to False to test quietly in class


# ---------- Connecting to the devices ----------
# Every device on the I2C wires has its own address (a number).
def open_device(address):
    device = os.open("/dev/i2c-1", os.O_RDWR)
    fcntl.ioctl(device, 0x0703, address)     # 0x0703 means "talk to this address"
    return device


# ---------- GrovePi+ helpers ----------
def grovepi_send(command, port, value):
    message = struct.pack("BBBBB", 1, command, port, value, 0)
    os.write(grovepi, message)
    time.sleep(0.02)


def make_output(port):
    grovepi_send(5, port, 1)         # command 5 = set a port to be an output


def turn_on(port):
    grovepi_send(2, port, 1)         # command 2 = digital write, 1 = on


def turn_off(port):
    grovepi_send(2, port, 0)         # 0 = off


# ---------- Speaker helpers ----------
def speaker_on():
    grovepi_send(4, speaker_port, 128)   # command 4 = analog write: makes a tone


def speaker_off():
    grovepi_send(4, speaker_port, 0)


def beep(seconds):
    if sound_on:
        speaker_on()
        time.sleep(seconds)
        speaker_off()


def siren(times):
    # "nee-naw": the speaker (low note) and the buzzer (high note) take turns
    # "for count in range(times)" repeats the block exactly 'times' times
    if sound_on:
        for count in range(times):
            turn_off(buzzer_port)
            speaker_on()
            time.sleep(0.3)
            speaker_off()
            turn_on(buzzer_port)
            time.sleep(0.3)
        turn_off(buzzer_port)


# ---------- LCD helpers ----------
# The LCD has two addresses: one for the text, one for the coloured backlight.
def lcd_command(code):
    os.write(lcd_text, struct.pack("BB", 0x80, code))
    time.sleep(0.005)


def lcd_setup():
    lcd_command(0x01)       # clear the screen
    time.sleep(0.05)
    lcd_command(0x0C)       # screen on, no cursor
    lcd_command(0x28)       # use both lines
    os.write(lcd_backlight, struct.pack("BB", 0, 0))      # wake up the backlight chip
    os.write(lcd_backlight, struct.pack("BB", 1, 0))
    os.write(lcd_backlight, struct.pack("BB", 8, 0xAA))


def lcd_colour(red, green, blue):
    # each colour is a number from 0 (off) to 255 (full)
    os.write(lcd_backlight, struct.pack("BB", 4, red))
    os.write(lcd_backlight, struct.pack("BB", 3, green))
    os.write(lcd_backlight, struct.pack("BB", 2, blue))


def lcd_write_line(code, text):
    lcd_command(code)                    # 0x80 = start of line 1, 0xC0 = start of line 2
    text = text.ljust(16)                # pad with spaces to clear old letters
    for letter in text:
        # ord() turns a letter into its number code, which is what the LCD needs
        os.write(lcd_text, struct.pack("BB", 0x40, ord(letter)))


def lcd_show(line1, line2):
    # Each line holds 16 characters - keep messages short!
    lcd_write_line(0x80, line1)
    lcd_write_line(0xC0, line2)


# ---------- Set up ----------
signal.signal(signal.SIGINT, signal.SIG_DFL)     # make Ctrl+C stop the program quietly

grovepi = open_device(0x04)
lcd_text = open_device(0x3E)
lcd_backlight = open_device(0x62)

make_output(buzzer_port)
make_output(speaker_port)
turn_off(buzzer_port)
speaker_off()
lcd_setup()

# ---------- Main program ----------
lcd_colour(255, 120, 0)                          # orange
seconds_left = countdown_from
while seconds_left > 0:
    lcd_show("Get ready...", "Siren in " + str(seconds_left) + " sec")
    print("Siren in", seconds_left)
    beep(0.1)
    time.sleep(0.9)
    seconds_left = seconds_left - 1

lcd_colour(255, 0, 0)                            # red
lcd_show("!!! NEE-NAW !!!", "Siren test")
print("Siren!")
siren(5)

lcd_colour(0, 255, 0)                            # green
lcd_show("All clear", "Mission 3 done")
print("Done.")

The brain

about 50 minutes
Goal

Put the pieces together into a real alarm: arm it, learn the room, watch, raise the alarm, and disarm with a secret PIN. Every alarm is written to a log file.

The five stages

The main program is one big while True: loop that goes around the five stages forever. The LCD colour tells you which stage you are in. Step through them.

greenred

Why two strikes?

Sensors are a little jumpy. One odd reading could be a fly, a draught or a glitch. The alarm only fires after two unusual readings in a row. Any normal reading in between resets the count to zero. That is the whole job of the strikes variable.

The program

This is the complete alarm. The helpers at the top are the ones you already know, plus one new sensor. The new ideas are marked. Three things you may not have seen before, each explained in a comment: for count in range(times), the % remainder operator ("every 25th loop"), and a function that returns two values.

# Mission 4 - THE BRAIN: Intruder Alarm
# GrovePi+ on a Raspberry Pi 5 (Kali Linux)
#
# Plug the parts into the GrovePi+ like this:
#   Green LED           ->  D2
#   Red LED             ->  D3
#   Ultrasonic ranger   ->  D5
#   Speaker             ->  D6
#   Buzzer              ->  D7
#   Temp & humidity     ->  D8   (the blue DHT11 sensor)
#   Light sensor        ->  A0
#   LCD RGB Backlight   ->  any I2C port
#
# Run with:     sudo python3 intruder_alarm.py
# Press Ctrl+C to stop.
#
# How it works:
#   1. ARMING   A countdown that beeps every second while you leave the room.
#   2. LEARNING The alarm measures what "normal" looks like: the distance to the
#               wall or door, and how bright the room is.
#   3. ARMED    It keeps checking. Someone walking through the ultrasonic beam makes
#               the distance shorter. A torch, or a light being switched on or off,
#               changes the light level. It also watches the temperature, in case
#               of a fire. The screen shows the room's temperature and humidity.
#   4. ALARM    Red LED, a "nee-naw" siren (speaker and buzzer take turns), a red
#               screen - and the time, reason and room conditions go in a log file.
#   5. DISARM   Type the secret PIN to stop it. Every wrong PIN is logged and sets
#               the siren off again.

arming_delay = 10         # seconds you get to leave the room

light_change = 150        # light level changing by this much = intruder
heat_limit = 40           # temperature (C) that counts as a possible fire
sound_on = True           # set to False to test quietly in class
log_file_name = "intrusion_log.txt"

Goal

Control the USB office cannon from Python, aim it at the doorway, then plug it into your alarm so it fires when an intruder is caught.

Safety first. Foam rockets only, never anything else in the tubes. Never aim at a face. Agree on the "target zone" with your teacher before you arm it. The cannon is a toy, treat it like one.

A different kind of device

The cannon does not plug into the GrovePi+. It is a USB device, like a mouse, so it needs a different library (usb.core) and a different message. Every message is 8 bytes. The first byte is 2 for "move" (or 3 for "the light"), the second byte is the command, and the rest are zeros. There is no "move 10 degrees" command: you tell it to start turning, wait, then tell it to stop. Try it.

Command numberName in the programWhat the cannon does

2cannon_uptilts the barrels up
4cannon_leftturns left
8cannon_rightturns right
16cannon_firefires one rocket (takes about 4 seconds, then reloads the next tube)
32cannon_stopstops moving

# Mission 5B - RETURN FIRE: Intruder Alarm with USB Cannon
# GrovePi+ and USB Office Cannon on a Raspberry Pi 5 (Kali Linux)
#
# Plug the cannon's USB cable into any USB port on the Pi.
# Plug the parts into the GrovePi+ like this:
#   Green LED           ->  D2
#   Red LED             ->  D3
#   Ultrasonic ranger   ->  D5
#   Speaker             ->  D6
#   Buzzer              ->  D7
#   Temp & humidity     ->  D8   (the blue DHT11 sensor)
#   Light sensor        ->  A0
#   LCD RGB Backlight   ->  any I2C port
#
# Run with:     sudo python3 intruder_alarm_cannon.py
# Press Ctrl+C to stop.
#
# How it works:
#   1. ARMING   A countdown that beeps every second while you leave the room.
#   2. LEARNING The alarm measures what "normal" looks like: the distance to the
#               wall or door, and how bright the room is.
#   3. ARMED    It keeps checking. Someone walking through the ultrasonic beam makes
#               the distance shorter. A torch, or a light being switched on or off,
#               changes the light level. It also watches the temperature, in case
#               of a fire. The screen shows the room's temperature and humidity.
#   4. ALARM    Red LED, a "nee-naw" siren (speaker and buzzer take turns), a red
#               screen - and the time, reason and room conditions go in a log file.
#               Then the CANNON FIRES at the intruder!
#   5. DISARM   Type the secret PIN to stop it. Every wrong PIN is logged and sets
#               the siren off again.

# Every device on the I2C connection has its own address (a number).
def open_device(address):
    device = os.open("/dev/i2c-1", os.O_RDWR)
    fcntl.ioctl(device, 0x0703, address)     # 0x0703 means "talk to this address"
    return device


# ---------- GrovePi+ helpers ----------
# Every GrovePi+ message is 5 bytes: 1, the command number, the port, a value, 0
def grovepi_send(command, port, value):
    message = struct.pack("BBBBB", 1, command, port, value, 0)
    os.write(grovepi, message)
    time.sleep(0.02)


# The GrovePi+ answers with 3 bytes: a label, then a number split into two bytes
def grovepi_answer():
    reply = os.read(grovepi, 3)
    label, high, low = struct.unpack("BBB", reply)
    return high * 256 + low


def make_output(port):
    grovepi_send(5, port, 1)        # command 5 = set a port to be an output


def turn_on(port):
    grovepi_send(2, port, 1)        # command 2 = digital write, 1 = on


def turn_off(port):
    grovepi_send(2, port, 0)        # 0 = off


def read_distance():
    grovepi_send(7, ranger_port, 0)  # command 7 = ultrasonic read
    time.sleep(0.1)                  # wait for the echo
    return grovepi_answer()


def read_light():
    grovepi_send(3, light_port, 0)   # command 3 = analog read (0 = dark, 1023 = bright)
    time.sleep(0.05)
    return grovepi_answer()


def read_temperature_and_humidity():
    grovepi_send(40, dht_port, 0)    # command 40 = temp & humidity, 0 = blue DHT11
    time.sleep(0.6)                  # this sensor is slow
    reply = os.read(grovepi, 9)
    # The reply is 9 bytes: a label, then two decimal numbers of 4 bytes each.
    # "<Bff" means: B = one byte, f = a 4-byte decimal number, < = byte order
    label, temperature, humidity = struct.unpack("<Bff", reply)
    return temperature, humidity

    lcd_colour(0, 255, 0)                            # green
    lcd_show("Disarmed", "Rockets left: " + str(rockets_left))
    write_log("DISARMED after " + str(wrong_tries) + " wrong PIN(s)")
    print("Alarm stopped. Rockets left:", rockets_left)
    beep(0.1)                                        # two short "all clear" beeps
    time.sleep(0.1)
    beep(0.1)
    if rockets_left < rockets_per_alarm:
        input("Reload the cannon, then press Enter to arm again...")
        rockets_left = rockets_loaded
    else:
        input("Press Enter to arm the alarm again...")

One-time Pi setup (do once per Pi, or push with pifleet)

Kali on the Pi 5 does not enable I2C by default and has no raspi-config toggle for it. Edit the config file, install the tools, add the student account to the hardware groups, then reboot.

terminal · one time per Pi
$ sudo sh -c 'grep -q "^dtparam=i2c_arm=on" /boot/firmware/config.txt || echo dtparam=i2c_arm=on >> /boot/firmware/config.txt'
$ sudo apt update
$ sudo apt install -y i2c-tools python3-usb
$ sudo usermod -aG i2c,gpio,dialout,plugdev kali
$ sudo reboot

Replace kali with the student login if it differs. If python3-usb is not in the repo on a given image, sudo python3 -m pip install --break-system-packages pyusb does the same job. The programs run with sudo regardless, which avoids udev rules for the cannon.

USB power for the cannon. The cannon draws more than the 600 mA the Pi 5 allows its USB ports by default, and the firing motor is the hungriest part. With the official 27 W (5 V 5 A) supply the Pi raises the limit to 1.6 A automatically. With any other supply, add usb_max_current_enable=1 to /boot/firmware/config.txt and reboot, and expect low-voltage warnings if the supply is marginal.

Hardware notes and known limits
  • Board: this is written for the Dexter Industries GrovePi+ (I2C address 0x04), not the Seeed Base HAT. The 5-byte protocol and command numbers come from Dexter's firmware source. The ultrasonic reading has been verified on your board; the LCD, speaker and DHT code follow Dexter's own examples but were checked in simulation, so run Mission 3 yourself before the lesson.
  • Speaker: only D3, D5 and D6 can play a tone (PWM pins). The GrovePi+ gives a fixed pitch, hence the two-part siren. The blue potentiometer on the speaker module is the volume.
  • DHT11: about 0.6 s per reading and the occasional failed read (NaN). The alarm polls it every 25 loops and ignores readings outside 0 to 60 °C. Humidity from a DHT11 is ±5 %, good enough for a screen readout.
  • Ultrasonic: reliable from about 3 cm to 350 cm. Reading 0 means no echo. Soft furnishings and angled surfaces can swallow the echo; aim it at a flat wall or door.
  • Cannon: Dream Cheeky "Thunder" (USB ID 2123:1010), the model Dexter Industries used in the video this extension is based on. Pan is roughly 270°, tilt about 45°, four rockets, about 4 s per shot. The protocol (8-byte HID report, commands 1/2/4/8/16/32) is from Dexter's office_cannon_v1.py. If lsusb shows 0a81:0701 instead, that is the older model: change the usb.core.find line to those IDs and in cannon_send use cannon.ctrl_transfer(0x21, 0x09, 0x0200, 0, struct.pack("B", command)). The older model has no light.
  • Ctrl+C during an alarm leaves the buzzer on. Running any program again switches it off at start-up.
  • Pi 5 Active Cooler: the GrovePi+ will not seat over it. Use low-profile heatsinks or a stacking header on the fleet.

Differentiation and assessment
  • Support: the checkpoints are the minimum. A student who completes Missions 1 to 3 has met the hardware-control outcomes; Mission 4 can be run as a demo with them changing settings only.
  • Extend: the Tinker boxes escalate. The two-ranger sentry and the door counter are the genuinely hard ones.
  • Evidence: the log file is timestamped evidence of a working alarm. Ask for a screenshot of cat intrusion_log.txt plus a one-paragraph explanation of strikes.
  • Cybersecurity links: plaintext PIN in source, the wrong-PIN log as an attack record, getpass versus input (shoulder surfing), and why the Pi is "listening" on an unencrypted wire.
  • Quiz: ten questions on the page, self-marking, no storage. Answers are not shown until a choice is made.
